Enterprise Agentic AI Platform

The end-to-end user journey — what to click, what to fill in, and why each step matters.

The console is running at http://localhost:4000. This guide walks the L3 · Self-Service Scale story: a domain team self-services a new agent on top of a platform-owned Foundation Harness, tests it, evaluates it, and hands it off — without rebuilding identity, memory, observability, or guardrails.
Platform team — control plane (owns the catalog, blueprints, operations, observability) Domain team — application plane (composes & ships an agent)

0 · Overview

Open the console and land on Overview. This frames the whole demo: the platform team runs one control plane (catalog, blueprints, operations, observability, guardrails); domain teams work in the application plane, standing on a locked Foundation Harness and differentiating only in their Domain Harness (persona, skills, tools, memory, eval).

Why it matters: this is the hybrid pattern from the deck. The platform pre-wires the hard, compliance-heavy parts once; every domain team reuses them instead of re-implementing identity/observability/guardrails per project.

4 · Offline eval — golden dataset & the iteration loop domain team

On the test step (and on any deployed agent's detail page) there's an Offline eval · golden dataset card. This is the predefined eval pipeline that ships inside the Foundation Harness.

What to do

DatasetThe card lists the project's golden scenarios (inputs + expected behavior). it-helpdesk ships 8: SLA questions, VPN runbook, MFA-lost, out-of-scope, etc.
EvaluatorsTick the ones to score with — built-ins like Builtin.Correctness plus any custom judge like runbookAdherence (a custom LLM-as-judge that scores IT runbook discipline)
RunClick Run golden-dataset eval. It invokes the deployed agent for each scenario, waits ~3 min for trace ingestion, scores each with its own ground truth, and saves the run with aggregate scores.
The iteration loop (the whole point): change the model or the prompt, redeploy, run the eval again. Each run is saved with a model+prompt snapshot, so you compare before/after. In our test, tightening the IT prompt moved Correctness 0.69 → 0.75 and the custom runbookAdherence 1.63 → 2.13 — measured, not guessed.

Why it matters: this is what makes changing a deployed agent safe and fast. You get numbers back in minutes, so the develop → measure → improve loop is tight.

5 · Operate & Observability platform team

Operate

Click Operate — a single pane of glass over every deployed AgentCore runtime (live from AWS). Click a row (e.g. ithelpdesk_chat_agent) to open its detail: model, memory strategies, identity, skills, observability, plus a live streaming chat and the same golden-eval card.

Observability

Click Observability. Observability ships inside the harness — one set of OTEL spans, two backends:

Backend 1 · CloudWatchAgentCore-native pipeline; powers the L1–L4 metric layers (tokens, latency, reasoning cycles) and agentcore run eval
Backend 2 · LangfuseA second OTLP exporter added by the harness — per-trace timelines, token costs, per-user/session drill-down. Keys live in SSM (never in code). The page shows a live table of recent Langfuse traces.

Nothing to fill in — but this is a strong talking point: the domain team wrote zero observability code and gets two backends.

6 · Hand off to GitHub domain team

Back on the Build step 3, the Hand off card is the L3→L4 artifact: export a GitHub repo with the foundation code + a CLAUDE.md that guides the domain team's coding assistant.

GitHub accountAuthorize the account that should own this new private repository. Authorization is requested again for every repository.
Repository namee.g. it-support-demo — lowercase/digits/-_.; a duplicate name fails fast with a clear message
ActionApprove the immutable preview, then click Authorize GitHub and create repository

This is the bridge to L4 (Adaptive Platform): the same golden-path artifact that AI-assisted onboarding would generate — here produced by self-service.

In one sentence

A domain team stands on a platform blueprint, composes a persona + skills + tools, deploys a real agent with identity/memory/observability/guardrails they never had to build, proves quality against a golden dataset, and hands off a clean repo — the platform's paved road, self-served.
